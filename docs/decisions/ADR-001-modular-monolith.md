# ADR-001：采用模块化单体 + 领域分包

- 日期：2026-01-15
- 状态：已接受

## 背景

练手项目需要一个既能练习架构设计、又不会过早引入分布式复杂度的形态。
目标是让每个业务域边界清晰、可独立演进、可测试，同时保持单体部署简单。

## 决策

采用 **模块化单体（Modular Monolith）+ 领域分包 + 端口适配器**：

- 一个 Go 服务，内部按业务域拆包（`internal/<domain>/`）
- 每个域内四层：`api → app → domain ← infra`
- domain 定义端口（接口），infra 提供实现
- 组合根（`cmd/server`）唯一装配依赖

## 后果

- 好处：依赖方向清晰、业务规则可单测、可替换基础设施、AI 知道代码放哪
- 成本：需要维护接口与适配器；比“全部堆一起”多几层间接

## 替代方案

- 经典分层（endpoint/service/dao）：简单，但层职责容易腐化
- 微服务：当前规模不值得
- 整洁架构全集：学习价值高，但初期成本大，先保留 domain 最内层即可
